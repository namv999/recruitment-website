# Admin module: FE–BE contract

**Branch:** `feature/admin-management`  
**Transport:** ASP.NET MVC 5 form/query requests with Razor views (not JSON API).  
**Authorization:** every action is restricted to `UserRole.Admin` through the existing `AuthorizeRoleAttribute`. Unauthenticated users follow the existing login redirect; other roles go to Access Denied.  
**CSRF:** every POST form must include `@Html.AntiForgeryToken()`.

The FE owns page composition and styling. This document defines the routes, model fields, and business rules the views must follow. Do not bind or render EF entities directly; use the Admin ViewModels below.

After an Admin signs in, the FE should provide an Admin-only entry link to `/Admin`. The shared layout is maintained separately; coordinate any shared navigation change with its owner.

## Route and page map

| Page / route | Method | Model / input | Behavior |
|---|---|---|---|
| `/Admin` | GET | `AdminDashboardViewModel` | Summary counts and links to the management pages. |
| `/Admin/Users` | GET | Query: `keyword`, `role`, `status`, `page`; `AdminUsersViewModel` | Search/filter and paginate all user accounts. Never display password hashes. |
| `/Admin/ToggleUserStatus` | POST | Form: `id` | Switch `active` ↔ `inactive`; no hard delete. Admin accounts and the signed-in account cannot be changed. |
| `/Admin/Companies` | GET | Query: optional `verified`; `AdminCompaniesViewModel` | List companies, optionally filtered by verification state. |
| `/Admin/ToggleCompanyVerification` | POST | Form: `id` | Toggle `is_verified`. Revoking verification moves that company’s currently published jobs to `pending`, requiring a new review. |
| `/Admin/Skills` | GET | Query: optional `keyword`; `AdminSkillsViewModel` | List/filter skills and include category plus candidate/job usage counts. |
| `/Admin/SaveSkill` | POST | Form fields: `Id` (optional), `Name`, `CategoryId` (optional) | Create when `Id` is absent; update when present. Names must be non-empty, at most 100 characters, and unique ignoring case. Category must exist. |
| `/Admin/DeleteSkill` | POST | Form: `id` | Delete only when no candidate, job, or alias rows reference the skill. Otherwise show an error and retain it. |
| `/Admin/Categories` | GET | `AdminCategoriesViewModel` | Show skill groups and job categories, including usage counts. |
| `/Admin/SaveSkillCategory` | POST | Form: `id` (optional), `name` | Create/update a skill group; name must be unique ignoring case and 1–100 characters. |
| `/Admin/DeleteSkillCategory` | POST | Form: `id` | Delete only when it contains no skills. |
| `/Admin/SaveJobCategory` | POST | Form: `id` (optional), `name` | Create/update a job category; name must be unique ignoring case and 1–150 characters. Slug is generated by BE and made unique. |
| `/Admin/DeleteJobCategory` | POST | Form: `id` | Delete only when no jobs use the category. |
| `/Admin/PendingJobs` | GET | `AdminJobsViewModel` | List jobs whose status is `JobStatus.Pending`. |
| `/Admin/ApproveJob` | POST | Form: `id` | Only a pending job belonging to a verified company can be approved. Sets status to `published`, and updates `published_at` and `updated_at`. |

All successful mutations redirect back to the relevant list page and set `TempData["Success"]`. Business-rule or validation failures redirect to that page and set `TempData["Error"]`. Missing IDs return HTTP 404. FE should render these shared flash messages and should not infer success from a POST response body.

## ViewModel fields

### Dashboard — `AdminDashboardViewModel`

`TotalUsers`, `ActiveUsers`, `PendingCompanies`, `PendingJobs`, `TotalSkills`, `TotalJobCategories` (integers).

### Accounts — `AdminUsersViewModel`

Filters: `Keyword`, `Role`, `Status`; pagination: `Page`, `TotalPages`, `TotalItems`; rows: `Users`.

Each `AdminUserItemViewModel` has `Id`, `Email`, `Role`, `Status`, `CreatedAt`, `LastLoginAt`, `CanChangeStatus`. Only render the status-change form when `CanChangeStatus` is true. This page manages candidate and employer accounts; admin accounts are excluded. Account states are `active` and `inactive`.

### Companies — `AdminCompaniesViewModel`

`Verified` is nullable (all / verified / unverified); `Companies` contains `Id`, `Name`, `TaxCode`, `City`, `IsVerified`, `JobCount`. Verification is a POST action, not a GET link.

### Skills — `AdminSkillsViewModel`

`Keyword`, `Categories` (select options), and `Skills`. Each `AdminSkillItemViewModel` has `Id`, `Name`, `CategoryName`, `CandidateUsageCount`, `JobUsageCount`. `AdminSkillFormViewModel` has optional `Id`, required `Name`, optional `CategoryId`, and `Categories` for the form.

### Categories — `AdminCategoriesViewModel`

`SkillCategories` and `JobCategories`; each `AdminCategoryItemViewModel` has `Id`, `Name`, and `UsageCount`. Inline edit forms submit to the matching save action; delete forms submit to the matching delete action.

### Job review — `AdminJobsViewModel`

`Jobs`; each `AdminJobItemViewModel` has `Id`, `Title`, `CompanyName`, `CreatedAt`, and `ApplicationCount`. The current BE contract defines approval only. Do not offer a reject transition until its business status and resulting behavior are agreed.

## State and error handling rules

- Use `UserRole`, `UserStatus`, and `JobStatus` constants for values; do not duplicate state strings in FE logic.
- Account deactivation is soft deactivation (`inactive`), so records and their related data remain intact. The existing login action accepts only `active` accounts.
- Company verification and job approval are separate decisions. A pending job cannot become public while its company is unverified. If a company is later unverified, its published jobs return to `pending`.
- Referenced skills/categories cannot be hard-deleted because candidate profiles, job requirements, and jobs depend on them. The BE reports the conflict through the error flash message.
- IDs are database identifiers. The FE must post the row ID, and must not treat a row’s position in the current page as its ID.
- Keep destructive/status changes as POST forms with confirmation in the UI; never mutate state through GET.

## Required Admin views

The MVC view paths corresponding to these actions are `Views/Admin/Index.cshtml`, `Users.cshtml`, `Companies.cshtml`, `Skills.cshtml`, `Categories.cshtml`, and `PendingJobs.cshtml`. Forms should use the exact field/action names in the route map and bind the provided ViewModels.
